# 📁 Deixis Machines Output Files Guide

This guide explains all the logs, reports, and data files generated by the Deixis Ethical Analyzer system.

## 📂 Output Directory Structure

When you run an analysis, all outputs are saved to timestamped session directories:

```
automated_analysis_results/
└── session_YYYYMMDD_HHMMSS/
    ├── 📝 Markdown Reports (Human-Readable)
    ├── 📊 JSON Data Files (Machine-Readable)
    ├── 📈 CSV Files (Spreadsheet-Compatible)
    └── 📋 Metadata Files
```

## 📝 Markdown Reports (Human-Readable)

### 1. **FINAL_RESEARCH_REPORT.md** ⭐ *Most Important*
- **What it is**: Complete academic-style research report
- **Contains**: Executive summary, methodology, findings, conclusions
- **Use for**: Publications, presentations, sharing results
- **Key sections**:
  - Research questions and hypotheses
  - Methodology overview
  - Key findings with evidence
  - Statistical analysis
  - Limitations and future work

### 2. **research_report.md**
- **What it is**: Main research findings with detailed analysis
- **Contains**: Tables, metrics, cross-framework comparisons
- **Use for**: Understanding patterns across deictic frameworks
- **Key sections**:
  - Processing time analysis
  - Response length patterns
  - Agency distribution findings
  - Ethical framework analysis

### 3. **critical_analysis_report.md**
- **What it is**: Methodological critique and limitations
- **Contains**: Critical assessment of the research approach
- **Use for**: Understanding what the system can and cannot claim
- **Key sections**:
  - Methodological concerns
  - Validity threats
  - Interpretation limitations
  - Recommendations for improvement

### 4. **evidence_based_findings.md**
- **What it is**: Concrete findings backed by specific examples
- **Contains**: Actual LLM responses demonstrating patterns
- **Use for**: Supporting claims with evidence
- **Key sections**:
  - Specific response examples
  - Pattern demonstrations
  - Quantitative backing
  - Verified insights

### 5. **README.md**
- **What it is**: Session overview and navigation guide
- **Contains**: Summary of what was analyzed and generated
- **Use for**: Quick orientation to the session results

## 📊 JSON Data Files (Machine-Readable)

### 1. **raw_analysis_results.json** 
- **What it is**: Complete raw data from all analyses
- **Size**: Large (5-10MB)
- **Contains**: Every response, metric, and analysis result
- **Structure**:
```json
{
  "dilemma_id": {
    "framing_type": {
      "llm_response": "...",
      "agency_analysis": {...},
      "ethical_analysis": {...},
      "rhetorical_analysis": {...},
      "processing_time": 15.2,
      "model_used": "gpt-4"
    }
  }
}
```

### 2. **comparative_reports.json**
- **What it is**: Cross-framework comparison data
- **Contains**: Aggregated metrics comparing all 8 frameworks
- **Use for**: Statistical analysis, pattern identification
- **Key metrics**:
  - Average processing times by framework
  - Response length distributions
  - Agency patterns across frameworks
  - Ethical reasoning variations

### 3. **session_data.json**
- **What it is**: Rich logging data from analysis session
- **Contains**: Detailed logs of every operation
- **Use for**: Debugging, verification, audit trail
- **Includes**:
  - Timestamp for each operation
  - Model selections
  - Temperature settings
  - Error logs if any

### 4. **analysis_report_TIMESTAMP.json**
- **What it is**: Structured analysis summary
- **Contains**: Key findings in JSON format
- **Use for**: Programmatic access to results

### 5. **critical_analysis.json**
- **What it is**: Critical insights in structured format
- **Contains**: Methodological assessments
- **Use for**: Understanding limitations programmatically

### 6. **evidence_based_analysis.json**
- **What it is**: Evidence-backed findings in JSON
- **Contains**: Concrete examples with metadata
- **Use for**: Extracting specific evidence

### 7. **session_summary_TIMESTAMP.json**
- **What it is**: High-level session metadata
- **Contains**: Runtime, counts, configuration
- **Use for**: Quick session overview

## 📈 CSV Files (Spreadsheet-Compatible)

### 1. **deictic_analysis_TIMESTAMP.csv**
- **What it is**: Tabular data for spreadsheet analysis
- **Contains**: One row per analysis (80 rows total)
- **Columns**:
  - dilemma_id, dilemma_title, framing_type
  - response_length, processing_time
  - agency_scores, ethical_metrics
  - rhetorical_markers
- **Use for**: Excel/Google Sheets analysis, statistical software

### 2. **for_R_analysis_TIMESTAMP.csv**
- **What it is**: R-compatible format
- **Contains**: Cleaned data ready for R statistical analysis
- **Use for**: Academic statistical analysis in R

## 🔧 Other Files

### 1. **for_python_analysis_TIMESTAMP.pkl**
- **What it is**: Python pickle file
- **Contains**: Complete Python objects
- **Use for**: Loading directly into Python for further analysis
```python
import pickle
with open('for_python_analysis_20250730_224025.pkl', 'rb') as f:
    data = pickle.load(f)
```

### 2. **README_RESULTS.json**
- **What it is**: File manifest and guide
- **Contains**: Description of all generated files
- **Use for**: Understanding what each file contains

## 📊 Typical File Sizes

- **Markdown reports**: 10-50 KB each
- **raw_analysis_results.json**: 5-10 MB
- **Other JSON files**: 100-500 KB each
- **CSV files**: 200-500 KB
- **Total session size**: ~10-15 MB

## 🔍 How to Use These Files

### For Academic Papers:
1. Start with `FINAL_RESEARCH_REPORT.md`
2. Extract tables from `research_report.md`
3. Get specific examples from `evidence_based_findings.md`
4. Address limitations from `critical_analysis_report.md`

### For Data Analysis:
1. Load `deictic_analysis_TIMESTAMP.csv` into Excel/SPSS/R
2. Use `raw_analysis_results.json` for custom analysis
3. Import `for_python_analysis_TIMESTAMP.pkl` for Python work

### For Presentations:
1. Use visualizations from reports
2. Extract key findings from `FINAL_RESEARCH_REPORT.md`
3. Show specific examples from `evidence_based_findings.md`

### For Verification:
1. Check `session_data.json` for operation logs
2. Verify counts in `session_summary_TIMESTAMP.json`
3. Cross-reference with `README_RESULTS.json`
